Reference

Tables of what claw-drive exposes.

MCP tools

ToolPurpose
start_sessionStart a driven session. Returns {session_id, watch_command, notification_contract}. The notification_contract field describes the session's vocabulary, surface modes, watch flags, and idle default — drivers can read it instead of hardcoding to a specific claw-drive version. Optional wrapper: false opts out of the sentinel-token wrapper (B doesn't receive the system-prompt injection); when set, notification_contract.wrapper_enabled is false. Optional name assigns a reusable alias (see Session aliases).
stop_sessionReap B. Keeps the session dir for inspection.
send_turnNon-blocking send of a user turn to B. Returns turn_id.
poll_turnFetch events and status for one turn. Supports long-poll. A tool_decision_required in the result carries the decision's rationale + (Edit/Write) diff.
poll_sessionTail all events for a session. Use sparingly — MCP token cap. tool_decision_required events carry rationale + (Edit/Write) diff.
list_sessionsList live and orphaned sessions.
resolve_tool_callApprove/reject a paused tool call. Optional remember_as_policy, preview_only (return the rule that would be remembered — no resolve, no mutation), and remembered_rule (append an explicit, edited rule).
update_policyReplace a session's policy at runtime.
interrupt_turnSIGINT B to cancel the current turn. For ~15 s afterwards rotate_session refuses with INTERRUPT_GRACE — an interrupted claude process can exit on its next turn; a completed turn clears the window early.
provide_tool_outputInject human-run command output back into B's conversation. Auto-resolves pending defer.
rotate_sessionRotate a driven session at its context threshold: B writes a structured handover, a successor spawns in the same cwd under the same policy (handover + the lineage's verbatim original mission in its first turn), any alias transfers, and the predecessor stops after emitting session_rotated. Structured refusals (TURN_IN_FLIGHT, DECISIONS_PENDING, INTERRUPT_GRACE, MAX_GENERATIONS, …) leave the session running. LONG-RUNNING: the handover is a real model turn.
recover_sessionContinue a DEAD session (crashed, killed, rebooted) from the freshest handover: reuses the runner's crash-handover.md or distills one from events.jsonl via a one-shot minimal-mode claude -p, then spawns a successor exactly as rotation does (lineage stamped, alias re-claimed if free). Takes the canonical sess_… id; optional model and no_start.

CLI commands

CommandPurpose
helpPrint the full capability map: the Session A/B model, the driving loop, the policy/gate/budget model, the sentinel vocabulary, fleet view, and every CLI command and MCP tool. --help, -h, and a bare claw-drive print the same guide.
sessionsList sessions (live and orphaned).
status [<session>] [--json]Fleet snapshot — one row per live session (state, last token, pending-decision count). With a session argument, just that one. --json for structured output. The point-in-time companion to watch --all.
show <session>State plus last 20 events.
report <session> [--json] [--idle-after SECONDS]Human-readable session report rendered from events.jsonl: a summary header (id, alias, cwd, model, started/ended, duration, exit reason, turn/tool-call/decision counts) followed by a chronological transcript — user turns, assistant text, one line per tool call with its policy resolution and how any pause was resolved, sentinel outcomes, idle gaps (--idle-after, default 600), and lifecycle markers. --json emits the summary object only. Works for live and dead sessions; strictly read-only.
tail <session> [--since N] [--follow]Stream events from a sequence number.
pending [<session>]List awaiting-approval calls. Each entry carries the decision's rationale and, for Edit/Write, a diff.
approve <call_id> [--reason R] [--remember | --remember-as JSON] [--preview] [--json]Approve a paused call.
reject <call_id> [--reason R] [--remember | --remember-as JSON] [--preview] [--json]Reject a paused call.
defer <call_id> [--reason R] [--remember | --remember-as JSON] [--preview] [--json]Defer a paused call to the human.
send <session> "<msg>"Send a user turn.
start --cwd PATH [--policy FILE] [--brief FILE] [--name ALIAS] [--no-wrapper]Start a session from the CLI. --name assigns a reusable alias usable in place of the canonical id at any session-arg command (see Session aliases). --no-wrapper starts B without the sentinel-token wrapper — pair with watch --no-token-filter.
stop <session>Reap B.
rotate <session>Rotate a session at its context threshold (see rotate_session above). Available once the policy's rotation block is configured; the driver typically calls it when context_threshold_reached fires.
recover <session_id> [--no-start] [--model M]Continue a dead session from its crash-handover (or distill one now), spawning a successor with lineage stamped. --no-start writes the handover only; --model overrides the distiller's model.
interrupt <session> <turn>SIGINT B.
policy <session> [--set FILE] [--show]View or replace a session's policy.
policy-test '<command>' [flags]Diagnose a tool call against a policy. See Policies → Testing a policy.
policy lint <file> [--check-coverage] [--json] [--max-severity warn|error]Analyze a policy file for structural problems (shadowed/unreachable, overly-broad, known-FP). A policy already fails to load on an uncompilable bash_command_matches or arg_matches, so lint's own regex-compile check only reports for a policy built in-process rather than read from a file. See Policies → Linting a policy.
prune [--older-than 24h]Remove dead sessions older than cutoff.
watch <session> [--since N | --replay] [--only KIND[,KIND]... | --decision-only] [--no-token-filter] [--idle-after SECONDS] [--no-suspected-needs-input] [--follow-lineage]Stream noteworthy events as JSONL. Used by Monitor flows. Sentinel filter is on by default — turn_completed surfaces only when the trailing token is [NEEDS-INPUT] or [DONE]. --no-token-filter disables the filter entirely. --decision-only and --only are kind-level filters that compose with the sentinel filter. --idle-after SECONDS emits a synthetic idle event after N seconds of no surfaced activity (default 600; 0 disables). The silent-miss backstop surfaces a no-token turn_completed whose final line ends in ? with an additive suspected_needs_input marker; --no-suspected-needs-input disables it. See Driving patterns → Sentinel tokens. With --follow-lineage, the stream follows the session's rotation lineage: when the watched session rotates — or a crashed member is recovered — the watcher hops to the successor and continues, until a member stops without a successor. Every line then carries the additive session_id/alias/generation fields (the --all trio); --replay replays the lineage from the watched session onward, --since N applies to the named session only. Mutually exclusive with --all.
watch --all [same flags except --follow-lineage]Merge every live session into one JSONL stream, each line tagged with an additive session_id. Dynamic membership — sessions spawned later join via a periodic rescan, a stopping session closes only its own tail (its session_stopped surfaces first), and the stream runs until SIGINT. Every single-session filter applies independently per session. status (no argument) is the point-in-time fleet-snapshot companion. See Driving patterns → Watching a fleet.
provide-output <call_id> [flags]Relay human-run output to a deferred call.

Session aliases

A session can be given a human-friendly alias at start — claw-drive start --name <alias> (CLI) or start_session({ name }) (MCP) — and used in place of the canonical sess_… id at any command or tool that takes a session argument.

  • Constraints: 1–32 chars, leading letter, then letters / digits / _ / -; must not begin with sess_.
  • Uniqueness: unique among live sessions. A duplicate-live alias fails at start with an error naming the conflicting session_id; once the holder stops or is pruned, the alias is free to reuse.
  • Resolution: every session-arg CLI subcommand (send, stop, interrupt, policy, tail, show, report, single-session watch, single-id status, single-target pending) and MCP tool (stop_session, send_turn, poll_turn, poll_session, provide_tool_output, update_policy, interrupt_turn) accepts either an alias or a canonical id.
  • Display: status, sessions, pending, and watch --all show the alias alongside the session_id when present.

An alias lives with its session: there is no post-start rename, no cross-restart registry, and no namespacing. start still prints the canonical session_id.

Runner log

Each driven session writes <session_dir>/runner.log — the runner's own stdout/stderr (startup, stdout-loop, and teardown errors) plus Session B's stderr, captured in-process because the runner is spawned detached with stdio:"ignore". It's where to look when a Session B won't start or dies unexpectedly.

The log is bounded by size-based rotation: runner.log rolls to runner.log.1 when it would exceed LOG_MAX_BYTES (default 10 MiB), keeping up to LOG_KEEP (default 3) generations (runner.log.1 … runner.log.<KEEP>) and deleting the oldest. Override via the CLAW_DRIVE_LOG_MAX_BYTES and CLAW_DRIVE_LOG_KEEP environment variables; an absent or invalid value falls back to the default, so the bound is never disabled. Plain text only — no log levels, no time-based rotation.

Compatibility

claw-drive 1.0 is a stability promise. The versioning follows SemVer. Within the 1.x line, releases may be additive — new tools, new fields, new event kinds, new CLI subcommands or flags, new sentinel tokens — but will not remove, rename, or incompatibly change anything listed below. Breaking changes are reserved for 2.0.

The full stability contract, including the additive vs. breaking distinction and frozen field-level details, is in COMPATIBILITY.md at the repository root.
